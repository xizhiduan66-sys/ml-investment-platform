# 模型诊断

模型评价与交易回测分开。指标按预测任务统一，模型结构决定专属诊断。新实验的完整报告保存在结果 JSON 的 `diagnostics` 字段，现有实验详情 API 和 JSON 导出直接提供该字段。

## 用户入口

1. 在「模型库」查看每种模型的诊断能力。
2. 当前三步创建界面不展示评估参数，使用单次训练。API 保留 LSTM / GRU 1–3 个固定随机种子诊断能力；增加次数会增加训练耗时。
3. 完成实验后，在详情顶部查看「模型预测质量」。默认展开验证集诊断，可切换训练集、验证集、测试集。
4. 交易表现位于模型诊断之后，使用独立的说明和指标区域。

旧实验没有完整的训练/验证预测记录，不自动填造报告。页面提示复制配置重跑，既有结果保持不变。

## 任务统一评价

所有分区均评价同一个最终模型；LSTM / GRU 使用验证损失选中的检查点。

| 任务 | 指标 | 图表与诊断 |
|---|---|---|
| 回归 | MAE、RMSE、R²、Pearson、Spearman、方向准确率、平均偏差 | 预测与实际散点、残差直方图、残差分位数、绝对误差 P95 |
| 二分类 | ROC-AUC、Average Precision、Log Loss、Brier、Accuracy、Precision、Recall、Specificity、F1、真实/预测正类比例 | ROC、PR、混淆矩阵、概率校准曲线、分箱样本量、ECE |

回归指标使用原始收益率比例单位；残差定义为预测减实际；方向准确率按 sign 一致计算，零收益作为独立方向。R² 在标签无方差时返回 null；相关性在任一变量无方差时返回 null。

分类指标固定使用 `pred >= 0.5` 判为正类，与交易开仓门槛分离。单一类别分区不定义 AUC/AP；precision/recall 等分母为零时返回 null。前端显示「—」，不将未定义指标伪装为 0。

AP 为 sklearn 的 Average Precision，不是梯形积分的 PR-AUC。Log Loss 使用 [1e-7, 1-1e-7] 裁剪概率；Brier 与校准评价使用原始概率。校准分箱固定 10 档，左闭右开，最后一档包含 1；ECE 为各箱绝对校准误差按样本量加权平均。这里只诊断校准程度，不自动拟合概率校准器。

历史 Ridge / Logistic 系数报告及 CNN-LSTM 诊断仍可阅读，但不能再创建这两类模型的训练任务。

## 基线与时间稳定性

此处是诊断使用的恒定预测参考，不是已移除的 Ridge / Logistic 训练模型。

- 回归基线：恒定零收益、训练标签均值。
- 分类基线：训练标签正类比例。
- 验证集和测试集绝不参与基线参数估计。
- 主误差改善率为 `1 - 模型误差 / 基线误差`；回归使用 RMSE 对训练均值基线，分类使用 Log Loss 对训练正类比例基线；基线误差为 0 时改善率不定义。
- 各分区按有效样本时间顺序最多分四段，通常每段至少 20 个样本。每段分别报告指标与实际数量。
- 时间分段使用固定模型，不是 walk-forward 重训练。相邻多步标签可能重叠，未计算独立样本置信区间或统计显著性。

散点按时间等距最多保留 300 点，ROC/PR 最多保留 200 点用于展示；所有指标使用全部有效样本，曲线抽样不参与指标计算。报告数据按图表上限保存，避免重复保存三份完整特征和预测矩阵。

## 模型专属诊断

| 模型 | 已实现 |
|---|---|
| LightGBM / XGBoost | 训练/验证 RMSE 或 Log Loss 曲线、Gain/分裂次数重要性、实际迭代数、验证损失最低轮次 |
| LSTM / GRU | 同一轮末训练/验证损失、选中检查点、参数量、裁剪前梯度范数及裁剪比例、可选多种子重复诊断 |

LightGBM / XGBoost 保留固定迭代上限的训练策略（默认 100 轮，可在模型参数中调整），未启用早停；显示的验证最低损失轮次仅用于诊断，不替换最终模型。时序模型回归训练损失使用训练标签标准化尺度，报告里的 MAE/RMSE 已还原为原始收益尺度。

XGBoost 的 Gain 使用 `total_gain`（各特征累计分裂增益），分裂次数使用 `weight`；未使用的特征补零，并按训练特征顺序展示。

系数和树重要性描述模型对输入的使用方式，不等于因果贡献；相关特征会影响其分配。

时序模型多次训练使用种子 42、43、44，固定数据与超参数，各自按验证损失选择检查点。报告包含各次测试指标及均值、样本标准差、极值；始终保留 seed=42 为主模型、交易预测和产物，不按测试表现选择种子。重复 1 次时明确提示无法评价初始化稳定性；2–3 次的波动也只是初步诊断。

## 实现位置

- `quant/evaluation.py`：通用指标、训练基线、图表数据、分段评价、边界处理。
- `quant/models.py`：三分区预测与各模型的训练诊断；原三项返回接口保持兼容，`diagnostics=True` 时增加第四项。
- `quant/engine.py`：组装、重复训练与持久化；保持历史摘要字段兼容。
- `quant/app.py`：校验重复训练次数，保存诊断版本与种子列表。
- `web/diagnostics.mjs`：独立模型诊断视图和真实 XY 坐标图表。

## 验证

```bash
node --check web/app.js
node --check web/diagnostics.mjs
node --test tests/test_ui.mjs tests/test_diagnostics_ui.mjs
PYTHONPYCACHEPREFIX=/tmp/quant-pycache .venv/bin/python -m unittest discover -s tests -q
```

本轮验证结果：68 项后端测试、22 项前端测试全部通过，JavaScript 语法检查通过；LightGBM、XGBoost、LSTM、GRU 原生回归与分类测试均已运行。

新增检查包括：已知误差与混淆矩阵、常量/单类别/无正预测、非有限值和非法概率、训练基线隔离、分箱总量、分段总量、模型预测与产物一致、GRU 检查点及固定种子复现、LightGBM 两类任务、多种子不替换主模型、旧报告提示、前端分区切换渲染、空曲线和内容转义。

本机 LightGBM 单独导入时缺少系统 libomp，但经项目的 `dependency_status()` 先加载 PyTorch 后，使用其已加载的 OpenMP 库成功完成原生回归和分类测试；未修改系统依赖。部署到其他环境仍以实际依赖检查为准。

未执行真实浏览器的点击和视觉验收；前端验证覆盖无浏览器环境下的渲染逻辑。自动滚动重训练、正则化扫描、SHAP 和超参数搜索尚未实现。
